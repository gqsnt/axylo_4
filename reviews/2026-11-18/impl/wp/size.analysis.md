## Why `line` retains everything

The source metafile showed **zero contributing modules disappearing** when I switched from all exports to the bare `line` export. Only `index.ts` and `core/stages.ts` had lower attributed module byte counts. The production package exports a single prebundled ESM file, but the same result from source establishes the actual dependency problem. `sideEffects: ["*.css"]` is already in place. [Package metadata](/home/canarit/projects/axylo/packages/axylo/package.json:7) · [Build entry](/home/canarit/projects/axylo/scripts/build.mjs:7)

1. **`line` → `createChart('line', …)` → `createController(kind, …)`.** Area, bar, scatter, and donut call the same functions. The literal passed by each wrapper crosses the same runtime dispatch. The controller keeps its append implementation because every returned `Chart` exposes synchronous `append`, even on a page that has yet to stream anything. Its `openStore` directly references `AlignedStore.fromFrame`, `new PointStore`, and `new DonutStore`. [Entry points](/home/canarit/projects/axylo/packages/axylo/src/index.ts:14) · [Browser host](/home/canarit/projects/axylo/packages/axylo/src/core/chart.ts:129) · [Store dispatch](/home/canarit/projects/axylo/packages/axylo/src/core/controller.ts:555) · [Public handle](/home/canarit/projects/axylo/packages/axylo/src/core/controller.ts:1427)
2. **`update` → `resolveOptions` → `normalize` → `buildView`.** `keysForChart[type]` retains all option schemas. `normalize` calls `donutFrame`, `pointFrame`, or `alignedFrame`. `buildView` calls `buildDonut`, does scatter extent and range work, or builds aligned views with bar band and stack branches. Specializing the store alone leaves these static paths reachable. [Option resolution](/home/canarit/projects/axylo/packages/axylo/src/data/options.ts:209) · [Normalize](/home/canarit/projects/axylo/packages/axylo/src/data/normalize.ts:465) · [View dispatch](/home/canarit/projects/axylo/packages/axylo/src/view/index.ts:304)
3. **`frame` → axes, scene, lookup, reader, and DOM interaction.** `layoutInput` selects ring, bands, or XY. `buildScene` references arcs, bars, scatter points, area, and line. `buildLookup` switches between donut, scatter, and aligned lookup. `buildReader` calls `buildTable`, which has three frame-shape paths. The interaction factory branches on the same types for keyboard navigation, overlays, swatches, and the donut legend. [Controller dispatch](/home/canarit/projects/axylo/packages/axylo/src/core/controller.ts:1040) · [Axis dispatch](/home/canarit/projects/axylo/packages/axylo/src/core/axes.ts:79) · [Scene dispatch](/home/canarit/projects/axylo/packages/axylo/src/scene/index.ts:85) · [Lookup switch](/home/canarit/projects/axylo/packages/axylo/src/lookup/index.ts:8) · [Table switch](/home/canarit/projects/axylo/packages/axylo/src/reader/table.ts:78) · [Navigation dispatch](/home/canarit/projects/axylo/packages/axylo/src/dom/interaction.ts:465)
4. **`createChart` selects both renderers at runtime.** The private `__renderer` switch directly references both factories. Each factory’s mark switch references every mark painter, including arcs and bar patterns even when the scene can only produce line marks. The chart also directly creates the text layer, DOM figure and interaction layer, and installs styles and watchers. [Renderer choice and browser services](/home/canarit/projects/axylo/packages/axylo/src/core/chart.ts:60) · [SVG mark switch](/home/canarit/projects/axylo/packages/axylo/src/render/svg.ts:285) · [Canvas mark switch](/home/canarit/projects/axylo/packages/axylo/src/render/canvas.ts:160)

**Smallest restructuring that removes those edges.** Give each named chart entry a small private composition that supplies its option schema, normalizer and store opener, view and layout builders, scene and lookup builders, plus the type-specific navigation and reader operations. Keep one controller, one browser host, and one implementation of shared aligned data and Cartesian layout. Pass the aligned store its encoding operations so its re-encoding path can also avoid the all-type resolver. Split the two render switches into mark handlers shared by per-type renderer compositions. A line composition needs paths, points, rules and bands, including the points and rules used by focus. It can omit area fills, bar rectangles and arcs. Keep `validate(type, options)` on a separate, pure dispatch path so importing `line` alone cannot reach it. [Controller view and store calls](/home/canarit/projects/axylo/packages/axylo/src/core/controller.ts:416) · [Aligned store re-encoding](/home/canarit/projects/axylo/packages/axylo/src/data/store.ts:460) · [Validation](/home/canarit/projects/axylo/packages/axylo/src/index.ts:34)

Ship the production and development ESM graphs with those module boundaries intact. The package file allowlist and packed-content tests will need to admit the modules and any chunks. Keep the classic `Axylo` IIFE as a single, self-contained build of all exports. It can retain both renderers and the full interaction layer. The public names, options, handle signatures, and fixed core contracts can stay as they are. [Package allowlist](/home/canarit/projects/axylo/packages/axylo/package.json:8) · [Package-content tests](/home/canarit/projects/axylo/tests/dist/package-contents.test.ts:20) · [Public API](/home/canarit/projects/axylo/packages/axylo/src/public.ts:110)

I tested the dependency result with an in-memory `export { line }` entry. I folded the relevant chart-kind and frame-shape branches to line, replaced `openStore` with a direct aligned call, and removed the unreachable mark cases in each backend. This measured **81,704 gzip B (79.79 KiB)** with both renderers, down **18,032 B**. SVG alone measured **80,321 B (78.44 KiB)**. The metafile confirmed that point/donut stores, the scatter grid and point order, all scatter/donut lookup, and bar/area scene modules disappeared. This models the code the composition can omit. A production refactor will have dispatch and packaging overhead of its own.
