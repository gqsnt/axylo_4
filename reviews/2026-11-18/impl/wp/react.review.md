**B for shipping `be123ee`.** The documented `import { Line } from '@axylo/react'` fails. The most consequential runtime defect is the gap between React’s layout and passive effects. A parent can receive a ref whose chart is still `null`, or append to a chart whose new controlled data has committed in React but has yet to reach the core.

### Findings, most severe first

1. **B · The package exports files that the build never produces. Ran and inspected.** Node returned `ERR_MODULE_NOT_FOUND` for `@axylo/react/dist/index.js`. The declaration entry is missing too. The root build targets only `packages/axylo`, and the adapter’s TypeScript project has `noEmit`. The size test nevertheless passes at **984 B gzip** because it bundles `src/index.ts` in memory. With the installed esbuild, that direct entry retained `"use client"`; a bundle that re-exported `Line` from another entry lost it. Build the adapter JS and declarations, select the development hint appropriately, then import, type-check, server-render and measure the **packed export**. Assert the directive on the shipped entry. This blocks DX1, DX7, DX8 and DX10 release verification. [Package exports](/home/canarit/projects/axylo/packages/react/package.json:8) · [Build](/home/canarit/projects/axylo/scripts/build.mjs:5) · [Size test](/home/canarit/projects/axylo/packages/react/test/size.test.ts:10)

2. **M · The ref becomes observable before creation and before updates. Reasoned from the adapter and installed React 19.3.1.** `useImperativeHandle` publishes during layout. Creation and patching happen in passive effects. On mount, a callback ref or parent layout effect sees `handle.chart === null` and receives no notification when it becomes usable. On update, commit `data=B`, then call `append(row)` in the parent layout effect. The core receives `append` against A, followed by `update({data:B})`, which erases the row. A diagnostics read in that layout effect likewise describes A. The core obeys §1.5 call order throughout. Synchronize creation and accepted props in the child’s client layout phase before publishing the usable handle. Test this sequence without waiting for frames, including on Suspense reveal. This affects §1.7 streaming and DX5. [Adapter](/home/canarit/projects/axylo/packages/react/src/index.ts:53) · [React’s imperative-handle implementation](/home/canarit/projects/axylo/node_modules/react-dom/cjs/react-dom-client.development.js:9111)

3. **M · A committed handler change can still call the previous handler. Reasoned.** Commit `onDiagnostic=B` over A, then trigger a synchronous diagnostic through the ref from a parent layout effect. The stable forwarder still reads A. Removing `onHover` has the same window in which the removed callback can fire. Once passive effects run, present → absent → present works, and diagnostics from the adapter’s own `update` see the new handler. Publish the latest handlers in the child’s client layout phase before externally observable chart calls. Add replacement, removal and reinstatement tests that fire during the commit. This affects §1.7 handlers and §1.5 synchronous diagnostic delivery. [Forwarder and ref update](/home/canarit/projects/axylo/packages/react/src/index.ts:51)

4. **M · Explicit `undefined` can fail to restore a default. The reverse own-key transition also returns `null`. The test explicitly requires both results. Compare own-key presence as well as values and send an own `title: undefined` on the transition. Test against a prior imperative update so the reset has an observable effect. This violates §1.5 patch semantics and §1.7 removal semantics. 7. **M · Container attributes go to chart validation and disappear from the DOM. 12. **m · Deferring an effect error to component state can lose it. ### Areas examined and found sound

- **Committed renders.** Reasoned. Creation, diffing and writes to `applied` occur in effects. An abandoned render publishes no options, callback change or patch.
- **Normal lifecycle.** Reasoned. StrictMode deliberately creates twice with cleanup between setups. A key change disposes the old instance. A Fast Refresh remount or effect replay pairs successful setup with cleanup. The adapter’s normal path clears `live` before destruction. A caller who explicitly destroys the raw chart can still cause later adapter updates to reach it; §1.5 makes those calls no-ops.
- **Suspense and ref identity.** Reasoned for installed React 19. A Suspense fallback disconnects the layout ref while the existing chart’s passive effect can remain connected. Reveal can publish a new wrapper around that chart. With an unchanged ref, ordinary rerenders keep the wrapper stable. A saved getter reads `null` after actual passive cleanup; during StrictMode replay it can subsequently see the replacement chart.
- **Strict rejection and recovery.** Reasoned. A thrown `update` leaves `applied` at the last successful options, consistent with §1.5 rollback. The latest handler ref can already reflect the rejected render. Boundary remount gets fresh state. A strict `append` through the raw ref throws synchronously to its caller, and an event-handler caller must catch it there.
- **Ordinary patches.** Ran. Removing previously defined `data`, `x`, `y` and `onDiagnostic` emitted own keys with `undefined`. Missing required fields then reach core validation. Event props use subscriptions, with absent handlers becoming no-ops after synchronization. The diagnostic forwarder is installed for a supplied callback and cleared on removal.
- **Ordinary comparison.** Ran. Dense nested values replace whole options. Dates compare by timestamp, including two invalid dates. `NaN` compares equal and signed zeros differ. Functions, maps, typed arrays and class instances compare by identity. Data replacement uses identity; only the development hint inspects row endpoints or column references.
- **Source SSR and option types.** Ran. All five components rendered an empty div with deterministic class/style, a null server ref and zero factory calls. Each JSX prop type uses its corresponding public options type, including area stacking, bar layout, scatter field restrictions and donut fields. By inspection, the hooks and `forwardRef` used here are available in React 18.
