# Work package: a reference on a compact chart must have no effect

Read `AGENTS.md`. You own `packages/axylo/src/data/**`, `src/view/**`, `src/reader/**`, `src/diagnostics/**` and their tests, and `packages/axylo/test/acceptance/**` for one added test. Nothing else; do not commit. Another agent is editing `src/core`, `src/dom` and `src/theme`.

A reviewer of the documentation ran this (finding 11 of `reviews/2026-11-18/impl/wp/docs.review.md`): a compact line chart with values 2–4 and `reference: [{ y: 1000 }]` gets a y domain of [0, 1000], which flattens the sparkline, and the reference enters the generated description, although a compact chart draws no reference (spec 3.7, C1: "draws the marks and nothing else"; the scene already omits the mark). An option that silently reshapes the chart while showing nothing is exactly what spec principle F3 forbids ("reported, never guessed") and the registry has a code for an option that does not apply (AX150, see spec 3.5 and how `packages/axylo/src/data/options.ts` reports options that do not apply to a chart type).

Make `reference` on a compact chart (line, area or bar with `compact: true` or the object form) an option that does not apply: it is ignored everywhere (automatic domains in `src/view`, the summary and description in `src/reader`, any table or lookup text) and reported once through AX150 with the same level and effect the registry gives an inapplicable option, naming `reference` and saying compact charts draw no references. Changing `compact` from true to false through an update must bring the reference back (it stays in the accepted options; only its effect is suppressed while compact), and the diagnostic must appear and clear accordingly.

Tests first: unit tests in your modules for the domain, the summary and the diagnostic, for line, area and bar; one acceptance test in `packages/axylo/test/acceptance/compact.test.ts` titled in the suite's form (`C1 compact <kind>: a reference has no effect on the domain or the description and is reported as not applicable`), added to `EVIDENCE.json`. Check whether other options are in the same position on a compact chart (accepted, not drawn, still affecting something): `legend`, `zoom`, `tooltip`, `table`, axis `label`, `tickFormat`; list what you find and fix those that change what the reader gets without showing it, by the same rule; do not report options that are simply inert.

Run `timeout 300 npx vitest run packages/axylo/test/data packages/axylo/test/view packages/axylo/test/reader packages/axylo/test/diagnostics packages/axylo/test/acceptance`. Never leave a process running. Report: what changed, the tests, the other options you examined and what you did about each, the last lines of the run.
