# Code review: Axylo chart core, part 1

You are an independent reviewer from a different provider than the author of this code. Read-only: do not create, edit or delete files. Put everything in your final message. You cannot launch a browser in this sandbox: this is a review by reading, plus Node experiments on the parts that run without a DOM. Say for each finding whether you ran something or reasoned it out.

Under review: `packages/axylo/src/core/**` (except `contracts.ts`), `packages/axylo/src/dom/**`, `packages/axylo/src/index.ts`, the part of `packages/axylo/src/theme/css.ts` after the "structure" marker, and the tests in `packages/axylo/test/core/**` and `packages/axylo/test/browser/chart/**`. The author's brief and report are not in the repository; the requirements are these documents: `docs/03-plan-typescript-release.md` sections 1 (public API; 1.5 is the commit contract) and 2 (2.1 pipeline, 2.2 invalidation, 2.3 rendering, 2.4 document structure); `docs/02-product-spec.md` section 3.5 (diagnostic delivery), 3.7 (compact variant) and criteria F12, L3, L4, L7, L8, A1, C1–C5, I5, DX1, DX5, DX6, DX8; `packages/axylo/src/core/contracts.ts`; `packages/axylo/src/public.ts`; `AGENTS.md`. This code composes the other modules (data, diagnostics, scale, format, view, layout, scene, lookup, reader, messages, render, theme); read their index files as needed.

Find defects, most important first:

1. **Commit contract (plan 1.5).** Trace every public method through the controller and try to break the rules: ordering of calls made in one turn (update then append then zoom; append then update of data; zoom then update that changes the x domain); `chart.diagnostics` being current when each call returns; `strict` throwing from the right call and leaving the previous state fully intact (options, frame, store, view, diagnostics, DOM); a throw from inside the deferred frame; patch semantics (present key, `undefined`, absent) including nested objects such as `x` and `title`; `append` with `keep`, on charts that started empty, after an encoding change, on scatter and donut; zoom following the latest edge; `destroy` at every point (before the first frame, during a frame, twice, then other calls); re-entrancy (a listener or `onDiagnostic` that calls `update` or `destroy`); two charts on one page sharing nothing they should not.
2. **Atomic switch.** Can marks, text, lookup, the reader model or the figure ever show different revisions (for example the tooltip answering from a newer frame than the one drawn, or the summary describing data that is not on screen)?
3. **Invalidation (plan 2.2).** For each cached stage, find an input that changes without the stage rerunning (stale output) and a change that reruns more than it should. Check: title-only and description-only updates; data-only updates that change the value range; a resize; device pixel ratio changes; fonts finishing loading; locale and time zone options; theme and forced-colors changes; `colors`; `messages`; hidden series; zoom; state changes; a chart that starts hidden.
4. **Lifecycle and leaks.** Every observer, listener, media query, timer and animation frame: is it removed on `destroy`, on a failed creation, and when the target element is removed from the document without `destroy`? Anything retained after `destroy` (closures over frames, module-level caches such as the text measurement cache and the once-per-page diagnostic set growing without bound)?
5. **Figure and accessibility structure (plan 2.4; spec A1, C1, L7).** Roles and labelling for full and compact charts; unique ids; heading levels; `labelledBy` with and without a title; the summary's presence in the accessibility tree; state messages and their announcements (once, polite); the reader's note; the internal-error state; anything set with `innerHTML`; what an author-supplied string (title, labels, messages, formatter output) can inject.
6. **Sizing (spec L3, L8, C3).** Definite and indefinite heights, the 16:9 rule and its clamps, zero-size and hidden containers, containers that resize continuously, ResizeObserver loop risks, the compact variant's size.
7. **Diagnostics delivery (spec 3.5).** Once per code per page; hints only in development; `onDiagnostic` timing and duplicates; presentation-origin diagnostics; `strict` scope; `validate()` agreeing with what a created chart reports; what happens to diagnostics that stop applying after an update.
8. **Environment and measurement.** Locale and zone resolution; the text measurer agreeing with the text layer's real font, letter and word spacing; behaviour before fonts load.
9. **Public entry points.** Import without a DOM; target resolution; type signatures against `public.ts`; undocumented options leaking into types; the benchmark hook being absent from production builds unless the flag is set.
10. **Tests that do not test**, and requirements above with no test.

For each finding: severity (B blocks, M major, m minor), file and line, the concrete sequence of calls or situation, what goes wrong, what the plan or spec requires, and the fix. At most 20 findings, most severe first. No praise. End with one line per area you examined closely and found sound.
