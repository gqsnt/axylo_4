## Findings

### B1. The rendered scene cannot supply the exact data promised to readers

- Where: [Product spec, F2, F5, I1 and A1–A4](/home/canarit/projects/axylo/docs/02-product-spec.md:74), [TypeScript plan, §2.1–2.2](/home/canarit/projects/axylo/docs/03-plan-typescript-release.md:143)
- Evidence: **Observed.** The scene tags each primitive with a datum reference. The accessibility layer and hit index consume that scene, and dense lines keep only selected values. A4 exposes the first 1,000 rows. **Inferred.** A path can represent many observations, including values that were never emitted as vertices. Scene tags alone cannot recover those observations, missing-value positions, or exact ordinals. A reader can also see a spike near row 900,000 and have no way to retrieve it through the table.
- Change: Make a versioned, lossless normalized frame the source for exact lookup, summaries, navigation and the table. Derive geometry and interaction coordinates from the same frame revision and visibility state. Build the table on demand with native pagination and a way to jump by x or category. Test a million-point chart where a decimated-away value, a late spike and an explicit gap are all retrievable. Specify whether each surface describes the visible range or the full dataset.

### B2. A fixed number of vertices per pixel cannot preserve every gap and isolated point

- Where: [Product spec, F2, F5 and L5](/home/canarit/projects/axylo/docs/02-product-spec.md:77), [TypeScript plan, §2.2 and M6](/home/canarit/projects/axylo/docs/03-plan-typescript-release.md:173)
- Evidence: **Observed.** F5 triggers when points outnumber pixels. The plan triggers above twice the plot width and keeps first, min, max and last per column. F2 and L5 require every isolated point and forbid bridging gaps. **Inferred.** A column can contain hundreds of alternating valid and missing samples. Four vertices can lose isolated values or join separate runs. An O(visible points) scan also remains a redraw cost at full zoom, even if canvas commands are bounded.
- Change: Define one trigger in terms of backing-store pixels. Bucket each contiguous valid run separately and emit its selected vertices in source order. State the geometry bound in terms of both width and the number of visible runs. Limit the million-point performance claim to named data distributions until adversarial gaps are measured. Test alternating gaps, tied extrema, irregular spacing, viewport boundaries, DPR 1 and 2, and zoom levels that contain the outlier. Assert source indices and segment breaks directly. Use screenshots to check visibility at a specified stroke width and contrast.

### B3. The public types fail on their own examples and leave the data model ambiguous

- Where: [Product spec, W1 and DX2–DX3](/home/canarit/projects/axylo/docs/02-product-spec.md:133), [TypeScript plan, §1.2–1.4](/home/canarit/projects/axylo/docs/03-plan-typescript-release.md:36)
- Evidence: **Observed.** `Chart<Options>` uses an unbound `Row`. The column example passes the `Float64Array` and `Float32Array` constructors where `ArrayLike<unknown>` is declared. In-memory TypeScript 6.0.3 checks reproduced both errors. `keyof Row` alone checks key existence, and `Record<string, ArrayLike<unknown>>` loses the column keys. `CommonOptions` exposes `zoom` and `reference` before any chart-specific narrowing. **Inferred.** The draft provides no enforceable separation of wide `y` arrays from long-form `series`, and no contract for sparse series, unequal column lengths or missing values in typed arrays.
- Change: Publish complete declarations before building the public entry points. Use a chart- and input-specific handle, readonly row inputs, and a generic that preserves literal column keys. Make long and wide encodings mutually exclusive. Type fields by role and value compatibility, with runtime validation for untyped JSON. Specify equal column lengths, validity masks, sorting, duplicate policy per chart, and source-row provenance. Test missing keys, string-valued y fields, `Date` and epoch inputs, empty typed rows, column instances, invalid donut options, and long/wide/column inputs that normalize to equivalent geometry. Compare diagnostics against each input’s own row indices.

### B4. Updates, streaming and zoom have no shared commit contract

- Where: [Product spec, W4 and DX5](/home/canarit/projects/axylo/docs/02-product-spec.md:64), [TypeScript plan, §1.4–1.5 and §2.1](/home/canarit/projects/axylo/docs/03-plan-typescript-release.md:90)
- Evidence: **Observed.** `update(Partial<Options>)` applies next frame. `append`, `zoom` and interactive legend toggles also change chart state. The plan specifies identity-based memoization and a `max` append option, and gives `strict` a throw contract. **Inferred.** `update({ data: next })` followed by `append(batch)` has no defined destination. A deferred strict error has no delivery mechanism in the `void` signature. An in-place append can reuse stale domains and indexes, while a full re-normalization defeats the streaming fast path.
- Change: Define call-order processing and atomic publication of each accepted revision to marks, labels, hit testing and accessibility. Specify that omitted patch keys are retained, how a caller restores a default, how an invalid patch preserves the last committed chart, and how deferred failure reaches its caller. Define the initial streaming contract explicitly, including the unit of `max`, order and late-data rules, coalescing and overload behavior, zoom follow versus pinned view, and focus on eviction. Use bounded storage with a data revision and cancel pending commits on `destroy()`. Test replace→append→zoom in one turn, a rejected patch between valid operations, oldest-value eviction, and destroy before commit.

### B5. The first chart already exceeds the promised keyboard stop count

- Where: [Product spec, I2–I4 and A2](/home/canarit/projects/axylo/docs/02-product-spec.md:104), [TypeScript plan, §2.3 and M4](/home/canarit/projects/axylo/docs/03-plan-typescript-release.md:179)
- Evidence: **Observed.** A2 allows three stops. The proposed figure has a focusable plot, individually tabbable legend buttons and a table disclosure. A three-series chart therefore has five stops before the zoom reset. I3 supplies keyboard alternatives for gestures, while I4 only checks that touch works and targets have a minimum size. **Inferred.** A reset button and table pagination widen the contradiction. Keyboard shortcuts alone leave a gap for single-pointer users who cannot pinch or drag. [WCAG 2.2 pointer gestures and dragging movements](https://www.w3.org/TR/WCAG22/#pointer-gestures)
- Change: Give the collapsed chart at most three sequential stops: plot, a tested composite of chart controls, and table disclosure. Scope extra stops to the expanded table. Provide tap-operated zoom and pan or range controls that reach the same states as gestures. Define Escape to dismiss the tooltip first and exit exploration without moving focus out of the chart. Test forward and reverse traversal, expanded and zoomed states, focus after hiding a series, one-finger operation, page scrolling and an unobscured focus indicator on a dashboard.

### B6. The 1.0 performance gate calls for a probe that cannot run it

- Where: [Product spec, §5](/home/canarit/projects/axylo/docs/02-product-spec.md:145), [TypeScript plan, release definition and M6–M8](/home/canarit/projects/axylo/docs/03-plan-typescript-release.md:5), [Performance plan, §1–3 and §6](/home/canarit/projects/axylo/docs/04-plan-performance.md:3)
- Evidence: **Observed.** The spec calls for rebasing before gating. M6 calls for passing P1–P4 in the Phase 1 probe. Its timed cases are `scale` and `stream`, and it records neither timed hover nor verified presentation. P1 names “create to painted” but budgets scripting. P3 is absolute in the spec and called a uPlot ratio in Phase 3. Using the saved uPlot medians as written, P2’s ratio already implies caps of 47 and 123.6 ms, tighter than the stated 50 and 150 ms. **Inferred.** The documents allow different pass/fail results for the same build. [Phase 1 perf loop](/home/canarit/projects/axylo/research/harness/probe.mjs:162), [uPlot scale and stream samples](/home/canarit/projects/axylo/research/harness/perf.log:37)
- Change: Put the minimum Phase 3 measurement harness in M0–M1. Give every P criterion one normative workload, dataset shape, feature set, device profile, measurement boundary, statistic and threshold. Label the current numbers provisional until the first accessible vertical slice is measured. Use uPlot as a published comparison and set release gates from user-visible latency and frame pacing on named profiles. Keep the Phase 1 scoreboard as comparative evidence. Give 1.0 a separate acceptance matrix with justified “not applicable” entries.

### M1. F4 tests the wrong temporal type and contradicts its local-time default

- Where: [Product spec, F4 and §7](/home/canarit/projects/axylo/docs/02-product-spec.md:79), [TypeScript plan, fields and M2](/home/canarit/projects/axylo/docs/03-plan-typescript-release.md:54)
- Evidence: **Observed.** `trend.t` contains epoch milliseconds for UTC-midnight instants. The criterion requires identical text in three viewer zones and also defaults instants to the viewer’s zone. The field model says numeric values can be inferred and offsetless date-times are displayed as written. **Inferred.** A number cannot reveal whether it is a timestamp or a measure. An offsetless time cannot have a unique position on an instant axis around a DST fold without an interpretation rule. [Fixture generation](/home/canarit/projects/axylo/research/harness/src/data.js:6)
- Change: Test calendar dates and instants separately. Require invariant dates for validated `YYYY-MM-DD`, expected zone-dependent labels for viewer-local instants, and invariant labels when UTC or another fixed zone is declared. Require `type: 'time'` for numeric epochs and specify milliseconds. For 1.0, diagnose offsetless date-times with a concrete fix. Set the instant default before M1 and test invalid dates, leap day, and both DST transitions.

### M2. Zero, percent, explicit bounds and stacks use incompatible domain rules

- Where: [Product spec, F1, F7 and F10](/home/canarit/projects/axylo/docs/02-product-spec.md:76), [TypeScript plan, §1.2 and M2](/home/canarit/projects/axylo/docs/03-plan-typescript-release.md:59)
- Evidence: **Observed.** F7 requires a domain containing all data and ending at the first tick above the maximum, or at 100 for fields marked as percentages by label or format. M2 caps padding at one tick step. F1 requires zero, including for all-negative bars. The API also allows an explicit domain. F10 asks for a warning about missing stack values and leaves the plotted remainder unspecified. **Inferred.** The automatic minimum, maximum or both can legitimately extend several steps past the data. A percentage label cannot distinguish `0.82` from `82`, and an individually valid set of values can produce a larger stack total.
- Change: Define separate rules for automatic full domain, author bounds and zoomed viewport. Compute stack extents from independent positive and negative cumulative totals. Require declared percent units and input convention, with tests for ratios, percentage points and totals above 100. Remove truncated bars and filled areas from 1.0 unless the author deliberately selects a separately specified representation. Mark incomplete stack buckets visibly and preserve the underlying values in the table. Test constants, all-negative bars, mixed signs, missing components and reference lines outside the data range.

### M3. The severity contract permits silent production failures

- Where: [Product spec, F3 and DX4](/home/canarit/projects/axylo/docs/02-product-spec.md:78), [TypeScript plan, §1.5](/home/canarit/projects/axylo/docs/03-plan-typescript-release.md:105)
- Evidence: **Observed.** F3 says `strict: true` throws. The plan limits throws to error-level diagnostics, while AX103 and AX104 are warnings. DX4 promises field and row locations for every code, and the interface makes both optional. Production only calls `onDiagnostic`. **Inferred.** The smallest production call can omit its callback and render partial data or a blank chart with no explanation. A title or palette diagnostic may have no meaningful source row.
- Change: Publish the diagnostic registry with severity, affected input, geometry outcome, reader-facing outcome and strict behavior. State whether AX103 and AX104 throw in strict mode and whether coercion still reports AX104. Require source locations where applicable and a chart-level location otherwise. Surface a readable status for fatal invalid input and material data omission, even without a callback. Test construction and update in development, production and strict mode, with isolated invalid inputs and a valid missing-data control.

### M4. One formatter cannot guarantee compact ticks and exact readouts

- Where: [Product spec, F6](/home/canarit/projects/axylo/docs/02-product-spec.md:81), [TypeScript plan, field formatting](/home/canarit/projects/axylo/docs/03-plan-typescript-release.md:54), [Landscape, R4](/home/canarit/projects/axylo/docs/01-landscape.md:164)
- Evidence: **Observed.** The example puts `notation: 'compact'` on a field used across surfaces. F6 promises the data’s own precision and proposes scanning for `GMT` or a 13-digit number. Plotly’s captured `36.832k` corresponds to the fixture value `36,832`. **Inferred.** That example demonstrates abbreviation. It cannot prove rounding. The scan can also reject a legitimate 13-digit measure or a zone label. A JavaScript number carries no record of the trailing zeros in its source. [Plotly UTC hover capture](/home/canarit/projects/axylo/research/harness/shots/hover-utc-plotly.png), [Integer fixture generation](/home/canarit/projects/axylo/research/harness/src/data.js:13)
- Change: Separate tick formatting from canonical value formatting. Specify precision from the normalized numeric value or explicit author precision, with units shown consistently. Preserve a canonical value when a custom formatter abbreviates or throws. Assert expected strings for selected values in multiple locales, including large integers, small decimals, percentages and zoned times.

### M5. The layout invariant has no boundary for content or height

- Where: [Product spec, W3, L1–L3 and A6](/home/canarit/projects/axylo/docs/02-product-spec.md:63), [TypeScript plan, §2.1 and §5](/home/canarit/projects/axylo/docs/03-plan-typescript-release.md:158)
- Evidence: **Observed.** The spec allows labels of any length, a 240 px tile, a 16:9 fallback, a legend, headings and a table that reflows. L1 ends with a diagnostic suggesting horizontal bars. The plan proposes canvas text if DOM labels miss P5. **Inferred.** At 240 px the fallback is 135 px high. A warning cannot make the headings, controls and plot fit in that height. Canvas text can remove the visible user-spacing behavior the DOM architecture was chosen to provide.
- Change: Apply the aspect ratio to the plot region and let headings, controls and the expanded table flow outside it. When a fixed host cannot fit a readable plot, use a summary and data-view fallback with full labels that can be reached by touch or keyboard. Specify label density and minimum usable plot dimensions. Test real browser text boxes after web-font load, resize from a hidden tab, long unbroken labels, RTL, text-spacing overrides and 400% zoom. Retain the same tests for any renderer fallback.

### M6. The color rules contradict each other and ignore the background actually drawn

- Where: [Product spec, F9, L2, L4, A5 and DX6](/home/canarit/projects/axylo/docs/02-product-spec.md:84), [TypeScript plan, `palette` and theming](/home/canarit/projects/axylo/docs/03-plan-typescript-release.md:69)
- Evidence: **Observed.** F9 forbids color sharing and requires cycling above eight series. A5 puts alternate markers in the legend and tooltip, with line dashes contingent on contrast preferences. The plan also adds `palette: string[]` alongside CSS-only theming. The feasibility search specifies white and `#16181d`. **Inferred.** Defaults that pass on those surfaces cannot guarantee contrast against arbitrary inherited page colors, fills or image backgrounds. A marked legend cannot disambiguate two overlapping traces when their marks differ only by color. [Palette search inputs](/home/canarit/projects/axylo/research/palette/search.mjs:45)
- Change: Limit the built-in contrast guarantee to documented surfaces or validated token combinations. Define precedence for CSS tokens and any programmatic palette, or drop the latter. Require matching non-color identities on the marks and controls in ordinary modes too. Define the supported series count and what happens above eight. Test actual canvas strokes, area fills, slice boundaries, controls, focus and text in light, dark and Windows forced colors. Use OKLab separation as a palette check and test series identification separately.

### M7. Donut, scatter and references lack chart-specific behavior and limits

- Where: [Product spec, §2.1, F8 and I1](/home/canarit/projects/axylo/docs/02-product-spec.md:43), [TypeScript plan, common options, M5 and risks](/home/canarit/projects/axylo/docs/03-plan-typescript-release.md:69), [Performance plan, workload matrix](/home/canarit/projects/axylo/docs/04-plan-performance.md:21)
- Evidence: **Observed.** Donut scope says up to eight slices, while F8 merely hints above eight. I1 describes nearest x for every chart, while Phase 3 expects nearest-point scatter hover. Cartesian references have no geometry or accessible-label outcome. The plan can cut scatter’s grid index and only specifies a linear fallback below 5,000 points, while W-scatter includes one million. **Inferred.** The release can satisfy the shared fixture plan while leaving these charts undefined at valid inputs.
- Change: Add a capability and limits matrix by type. For donut, specify zero-valued slices, all-zero totals, duplicate labels and the ninth slice. Test ordered angles and a visible text key for small slices. For scatter, specify distance, hit radius, ties and coincident points. Set a measured upper bound or keep scatter provisional until a clustered-data benchmark passes, since a dense grid cell can still require a large scan. Test reference inclusion in domains, clipping, keyboard/table semantics and whether a reference may affect the data summary.

### M8. The tooltip criterion cannot be applied consistently to irregular series or small viewports

- Where: [Product spec, I1 and P4](/home/canarit/projects/axylo/docs/02-product-spec.md:103), [TypeScript plan, interaction module and M3](/home/canarit/projects/axylo/docs/03-plan-typescript-release.md:162)
- Evidence: **Observed.** I1 requires every series value at the nearest x within one frame, while keeping the tooltip in the viewport, away from the point and hoverable. M3 checks four edges and Escape. **Inferred.** Two series can have different observation times, and a large multi-series tooltip can occupy more than the free viewport. Dismissal is also ineffective if the next movement over the same anchor immediately reopens it. [WCAG 2.2 content on hover or focus](https://www.w3.org/TR/WCAG22/#content-on-hover-or-focus)
- Change: For shared-x line or area lookup, use the nearest visible x with a deterministic tie rule and show “No observation” where a series has no row. Keep explicit missing values distinct. Use the chart-specific pick rules from M7. Switch to a persistent bounded readout where the floating panel cannot fit. Specify keyboard focus, pointer transfer into the panel, Escape suppression until the anchor changes, and tap to pin or dismiss. Test sparse series, hidden series, edge and center positions, and a narrow tile with the maximum supported legend.

### M9. The accessibility release evidence leaves out author input, state changes and actual use

The figure sketch repeats `t` and `s` as IDs. A7 measures changes to a live region per chart, and A3’s manual script is a developer rehearsal. **Inferred.** The same title or description setup can pass a fixture and fail in a 24-chart page. [WCAG 2.2 full-page conformance](https://www.w3.org/TR/WCAG22/#cc2)
- Change: Require a meaningful author-supplied name for the documented accessible integration and generate unique references per instance. Keep mandatory semantic disclosures when custom prose is supplied. Announce loading, empty, error and recovery on state transitions. Separate user-requested point readouts from unsolicited stream summaries and test several concurrent streams. Publish fixture-specific WCAG outcomes and author obligations. Have screen-reader users complete find-a-value, compare-series and recover-from-an-update tasks before making a broad usability claim.

### M10. The React wrapper has undefined behavior on ordinary prop changes

- Where: [TypeScript plan, §1.6 and M7](/home/canarit/projects/axylo/docs/03-plan-typescript-release.md:131), [Product spec, DX5 and DX8](/home/canarit/projects/axylo/docs/02-product-spec.md:137)
- Evidence: **Observed.** The wrapper shallow-compares top-level options and calls `update` on prop changes. Its StrictMode outcome says the chart mounts once visibly. **Inferred.** Removing `tooltip={false}` can leave the old value in force if the wrapper sends only present keys. Replacing a handler can leave a stale subscription. A new identity for unchanged rows can reset a live window or zoom. Importing in Node only exercises the import boundary, while StrictMode cleanup and hydration exercise the component lifecycle.
- Change: Document immutable props and controlled `data` replacement. Define an explicit imperative streaming path if the adapter exposes one, including its interaction with controlled data. Route removed props through the core reset semantics and refresh listeners without recreating the chart. Test generic field inference in JSX, prop removal, callback replacement, interrupted lifecycle, setup–cleanup–setup, SSR hydration, two independent charts and no observer or queued-frame leaks after unmount.

### M13. The size and memory budgets omit the costs the architecture can incur

### M16. The selected ten are a judgement panel presented as a ranking

- Where: [Landscape, §1.1–1.3](/home/canarit/projects/axylo/docs/01-landscape.md:25), [Product spec, React adapter decision](/home/canarit/projects/axylo/docs/02-product-spec.md:178)
