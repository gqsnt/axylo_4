## What DX12 asks

"A coding agent gets the first chart right. Given fixed prompts and trap fixtures (UTC-midnight ISO dates, numeric strings, unsorted rows, missing days, a misspelled field), an agent with only the published docs produces a chart with no error diagnostics that passes the reader criteria. Recorded as agent rehearsal, not as user evidence."

The harness runs a coding agent on a task, then grades what it wrote, automatically and the same way every time. The coordinator runs it; you build and test it. The agents under test are command-line coding agents (Codex CLI and Claude Code); you do not need to run them (and should not: they need the network), but the harness must invoke them.

## Design (implement this; if a part cannot work as written, say why and do the closest honest thing)

1. **Fixtures**, `rehearsal/fixtures/`: small realistic JSON files, one trap or more each, values chosen so that a mistake is visible in the result:
   - `daily-visits.json`: 30 days of `{ "day": "2026-03-01T00:00:00Z", "visits": 1234 }` (instants at UTC midnight that mean calendar days; read in America/Los_Angeles they fall on the previous day: the trap), with three days missing (absent rows, not nulls) and the rows shuffled.
   - `regional-sales.json`: quarterly sales by region where values are numeric strings (`"1250.5"`), one region per row field.
   - `signups.json`: daily signups where the field is spelled `signpus` in the data while the prompt says "signups" (the misspelled field: the agent must notice the diagnostic, AX101, and use the real key, not invent data).
   - one combined fixture with several traps at once.
   Write each fixture's expected reading in `rehearsal/fixtures/<name>.expected.json`: what the chart's data table (spec A4, the "View as table" table) must show, row by row, as calendar dates or categories and numbers, derived by hand from the fixture's meaning (missing days are absent or "No data", never 0; dates are the calendar days the data means; numbers are numbers). Do not derive expected values by running Axylo.
2. **Prompts**, `rehearsal/prompts/<id>.md`, one per task (4 to 6 tasks), written as a developer would ask, in plain words, naming the data file and the chart wanted ("Show daily visits from data.json as a line chart titled 'Daily visits'."), never mentioning the trap. Each prompt also states the delivery contract (below) and that the only documentation available is in `docs/`.
3. **Workspace per run**, created by the runner outside the repository (in a directory the caller gives, default the session's scratch directory passed with `--workdir`): `docs/` = a copy of the built documentation site (`apps/docs/dist`, already built; copy, do not build), `node_modules/axylo` = the packed tarball unpacked (`tests/dist/.packed/axylo-0.0.0.tgz`, already packed), `data.json` = the fixture, `PROMPT.md` = the prompt, and a minimal `package.json` with `"type": "module"`. Nothing from the repository's source. The delivery contract: the agent writes `chart.js`, an ES module whose default export is `function render(element, data)` that draws the chart into `element` and returns the chart handle; it may use `import { line, bar, … } from 'axylo'`. It may run `node` (for example `validate` from `axylo`, which the docs describe) to check its work.
4. **Runner**, `rehearsal/run.mjs`: `node rehearsal/run.mjs --agent codex|claude --model <id> [--effort <e>] --task <id> --workdir <dir>`; prepares the workspace, runs the agent non-interactively in it with the prompt, with a time limit (default 20 minutes), and keeps the agent's full transcript:
   - codex: `codex exec -m <model> [-c model_reasoning_effort="<e>"] -s workspace-write --skip-git-repo-check -C <workspace> --json - < PROMPT.md > transcript.jsonl` (the observed model and effort are in `~/.codex/sessions/**/rollout-*-<thread_id>.jsonl`, `turn_context`; record them; the thread id is the first `--json` event);
   - claude: `claude -p --model <model> --output-format stream-json --verbose --allowedTools "Read,Write,Edit,Glob,Grep,Bash(node:*),Bash(ls:*),Bash(cat:*)" < PROMPT.md > transcript.jsonl` with the workspace as the working directory (observed model: the `model` field of the assistant messages).
   - **Audit**: after the run, scan the transcript for any file path outside the workspace that the agent read or ran (command lines, tool inputs): a run that touched the Axylo repository or anything outside the workspace other than system tools is recorded as void, with the paths.
5. **Grader**, `rehearsal/grade.mjs` (the runner calls it; it can also be run alone on a workspace): bundles `chart.js` with esbuild for the browser (as a consumer would, `conditions: ['browser']`, the production condition), loads it in system Chrome (playwright-core, headless, `channel: 'chrome'`) into a page with `<div id="chart" style="width:720px;height:400px">`, calls `render`, and judges, in two time zones (`America/Los_Angeles` and `Asia/Tokyo`, via the context's `timezoneId`):
   - **no error diagnostics**: no console message carrying an Axylo error-level code (the registry `packages/axylo/src/diagnostics/registry.ts` gives levels; production prints errors and warnings once per code) and the chart is not in its error state; warnings and hints are listed in the record, not failed, except AX140 (no title) which fails the reader criterion below;
   - **reader criteria**: the figure has an accessible name that is the title the prompt asked for (not the generated fallback, AX140); opening "View as table" shows exactly the expected rows of `<fixture>.expected.json` in both time zones (dates as the calendar days, missing days not shown as 0, values as numbers formatted as the table formats them: compare numbers by value, not by string); no "Values not shown" note unless the expected file says one is right; the chart type is the one asked for.
   - If `chart.js` is missing, does not export `render`, or throws: fail, with the reason.
   - Output: `grade.json` in the workspace: `{ pass, criteria: [{ name, pass, detail }], diagnostics: [...], timezones: [...] }`.
6. **Record**: the runner copies the transcript, the agent's `chart.js`, `grade.json` and a `run.json` (agent, requested and observed model and effort, task, start and end times, duration, exit, void or not with paths) into `rehearsal/records/<date>-<agent>-<task>-<n>/` inside the repository, so the record survives a restart. `node rehearsal/summary.mjs` prints a table of all records (agent, model, task, pass, failed criteria).
