## The defect

The plot's description (the `plotInstructions` message, `packages/axylo/src/messages/index.ts` line 62, written at `packages/axylo/src/dom/interaction.ts` about line 1866) is one fixed sentence: "Left and right arrows move between points, up and down between series, and Enter selects. Plus and minus zoom; 0 resets." It is shown on every chart. The Phase 1 rerun recorded it on a category bar chart and a donut (`research/harness/results.json`, `axylo.bars.aria` and `axylo.parts.aria`; analysis in `docs/05-comparison.md`, "Incorrect keyboard help"): neither can zoom (spec I3 and the type matrix in `docs/02-product-spec.md`; their toolbars show only "View as table"), and a donut has no series to move between. Spec A2/A3 and decision 0001 (`docs/decisions/0001-plot-interaction-pattern.md`) describe the keys; what a reader is told must match what the keys do on that chart.

## What to do

1. The instructions say only what applies to the chart as it is: the arrows' meaning by chart type (points along x; for a donut, slices; up and down between series only when more than one series is shown), Enter, and the zoom keys only where zoom is available (the same condition that shows the Zoom in button). Do it with the least change to the public `Messages` contract (`packages/axylo/src/public.ts`): for example `plotInstructions` keeps the navigation sentence and new keys (`seriesInstructions`, `zoomInstructions`, or one per chart family) carry the conditional parts, joined with a space. Author overrides must still work, and a page that overrode `plotInstructions` before must not end up with English appended to its own text: check how the message tests handle this (`packages/axylo/test/messages/index.test.ts`, and the acceptance test `packages/axylo/test/browser/acceptance/a6-a10.browser.test.ts`, whose `WHERE` table must list every key with where it is shown: you may edit that table and only that table there).
2. The text is updated when what applies changes (zoom turned on or off by `update`, a series hidden or shown so one or several remain), without rewriting the focused range's value text (decision 0004 part 2 is about the value text; this is the description).
3. Tests, expected texts written from the spec, not from the implementation: Node tests where the DOM-free host can see the description; browser tests in `packages/axylo/test/browser/chart/` for a line with two series and zoom (all parts), a line with one series (no series part), a category bar (no zoom part), a donut (slices, no series, no zoom), and a zoom turned off by `update`. Read how the existing tests in those directories open a page.
4. Documentation: the messages table (`apps/docs/data/messages.mjs`, the build fails if keys differ) and the accessibility page's keyboard section (`apps/docs/pages/accessibility.md`) say the instructions follow the chart.
